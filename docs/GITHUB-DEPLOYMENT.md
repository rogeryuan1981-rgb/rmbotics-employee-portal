# GitHub Pages 發布與資料庫分階段啟用

網站沿用既有的 GitHub Pages 工作流程，由 main 分支發布，網址為 `https://rogeryuan1981-rgb.github.io/snack-vote/`。使用同一來源與 hash 路由，既有零食連結保留。

2026-11-16 發布前的唯讀檢查顯示：既有網站可連線，且已有 Supabase 公開連線設定；但新平台的 `portal_rpc` 尚不存在（PGRST202）。因此發布版提供下列過渡處理：

- 僅當後端明確回報新平台 API 尚未建立時，入口顯示「教育訓練尚未開放」，保留既有零食前後台。
- 不在瀏覽器內建立假資料庫，不以模擬時數或前端評分啟用正式教育訓練。
- 權限拒絕、網路錯誤與其他後端錯誤維持拒絕存取，不藉過渡模式繞過權限。
- 新資料庫啟用後，入口每 15 秒重新檢查，可自動改用完整模組與獨立系統資格。
- 過渡期間，原零食名冊操作使用原有欄位；正式啟用後才使用新增的系統資格與停用原因。

正式資料庫遷移及真實寄信仍需另行授權。本次網站發布不會自動執行 SQL，也不會寄送員工驗證碼或訓練通知。

資料庫啟用需依 README-PORTAL.md 執行五份增量遷移，並明確指定第一位訓練管理員 Email。GitHub Pages 提供靜態前端；資料保存、可信任計時、評分與權限由 Supabase 負責，通知另需受信任工作程序。

驗證包括原有完整平台的瀏覽器流程，以及「新 API 未建立時零食仍可使用」與「權限拒絕不得退回舊模式」兩項部署情境。實際結果另見本次發布紀錄。
