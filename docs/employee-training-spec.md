## 2. 目標與範圍

建立共用員工登入入口，第一版連結教育訓練與零食投票，並保留後續串接客服系統的規劃。客服系統未在第一版實作實際介接。

教育訓練平台主要管理：

- 員工應完成哪些訓練。
- 是否在規定期限內完成。
- 學習時數與歷次測驗成績。

職務說明書用來連結職責、職務與訓練要求。現階段不納入員工是否勝任職務的能力認證。

## 4. 共用員工入口與身分

- 沿用 Email 一次性驗證碼登入，員工不需另外建立教育訓練密碼。
- 僅啟用的員工可登入。
- 登入一次後，可進入教育訓練與零食投票，不需再次輸入帳密或驗證碼。
- 入口以明確功能卡片呈現各系統。
- 各系統提供明確的「返回員工入口」。
- 統一維護員工身分及姓名、Email、到職日、部門、職務與在職狀態。
- 同一人可有多個職務，也可兼具多個管理角色。
- 各系統管理權限分開設定。零食投票管理員不自動成為教育訓練管理員。
- 共用入口與各系統均須遵守員工停用及登入失效規則。
- 既有個人電腦保留登入及共用電腦模式，納入整合檢視，不擅自移除。

## 5. 前台與後台

### 5.1 前台

所有角色的個人學習前台一致。主管、HR 與管理員在前台都只查看自己的學習資料。

前台需要非常直覺，有明確提示、操作路徑與返回入口。員工隨時能知道現在要做什麼、還差什麼與下一步在哪裡。

| 畫面或情境 | 要求 |
| --- | --- |
| 首頁 | 顯示待完成課程與期限，優先提示逾期及即將到期項目。 |
| 課程卡片 | 顯示截止日、累計與要求時數、進度及主要操作按鈕。 |
| 課程開始 | 說明完成條件，例如學習 60 分鐘且測驗達 80 分。 |
| 學習中 | 顯示累計時間、尚需時間及是否正在計時。 |
| 暫停計時 | 顯示原因及恢復方式。 |
| 時數未達標 | 說明尚需學習時間，不僅顯示無法點擊的測驗按鈕。 |
| 時數達標 | 明確提示可開始測驗，提供入口。 |
| 未及格 | 顯示分數與及格標準，提供錯題教材及重考入口。 |
| 完成 | 顯示完成日期、成績與是否準時，提供下一門課程入口。 |
| 再次進入 | 接續閱讀位置、影片播放位置及已累計進度。 |

狀態使用文字搭配顏色，不只靠顏色或圖示。手機及電腦都需方便使用。第一版同時支援手機與桌面響應式介面，不以裝置差異縮減核心功能。

### 5.2 後台

後台集中處理人員、職務、課程、題庫、指派、期限、報表與權限設定。可見選單與操作範圍依角色授權。

管理資料不得混入個人學習前台。有管理權限的帳號可切換後台。

## 6. 角色與權限

權限分為「允許操作的功能」與「適用部門範圍」。

| 功能 | 員工 | 主管 | HR | 後臺管理員 |
| --- | --- | --- | --- | --- |
| 自己的學習、測驗與紀錄 | 可 | 可 | 可 | 可 |
| 查看及管理部門訓練進度、成績 | 不可 | 負責部門 | 授權範圍 | 全平台 |
| 依職務挑選訓練、設定期限 | 不可 | 負責部門 | 授權範圍 | 全平台 |
| 直接指派訓練 | 不可 | 可，限負責部門 | 可，限授權範圍 | 可 |
| 維護人員、到職日、部門與職務 | 不可 | 未授權，不自行開放 | 可，限授權範圍 | 可 |
| 調整個別期限 | 不可 | 負責部門 | 授權範圍 | 全平台 |
| 查看及匯出管理報表 | 不可 | 負責部門 | 授權範圍 | 全平台 |
| 新增或修改課程、教材與題庫 | 不可 | 初期關閉，保留日後授權 | 初期關閉，保留日後授權 | 可 |
| 設定角色與權限 | 不可 | 不可 | 不可 | 可 |

- 主管可負責多個部門，部門以可複選方式授權。
- 主管可分部門檢視或合併查看負責部門。
- HR 管理範圍可設定全公司或指定部門。
- 同一人可同時是 HR 及主管。
- 「保留日後授權」表示權限設計可支援，不代表初期已開放。

## 7. 職務說明書與訓練關聯

- 職務說明書的工作職責不強制逐項設定訓練。
- 每項職責可連結零項、一項或多項課程。
- 主管也能直接為職務挑選課程，不必連到特定職責。
- 同一課程可供多個職責或職務使用。
- 員工應能看出課程來自哪個職務、職責或直接指派。
- 員工設定職務後，自動套用該職務訓練。
- 職務新增訓練時，自動套用到現任該職務的員工。
- 不把「每項職責都必須有課程」設為系統限制。

## 8. 訓練週期、指派與期限

### 8.1 可選期限方式

| 方式 | 起算或截止設定 |
| --- | --- |
| 到職日起算 | 到職後指定天數內完成。 |
| 接任日起算 | 調職或新增兼任職務後指定天數內完成。 |
| 指派日起算 | 指派後指定天數內完成，例如補訓。 |
| 當年度固定期限 | 當年度指定月日前或指定月底前完成。 |

每項訓練要求可以設定適合的期限方式，不必所有課程採同一方式。

### 8.2 新課程套用現任員工

- 新增訓練後自動套用現任員工。
- 若員工依到職日或接任日推算，已超過該新訓練原訂期限，改以新增指派日加補訓天數。
- 新增時可設定補訓天數。
- 原本已指派且逾期的訓練，不因一般設定異動而自動展延。

### 8.3 一次性與每年必修

- 課程可設定一次性必修或每年必修。
- 每年必修自動對符合職務條件的員工產生當年度要求。
- 各年度重新累計時數並通過測驗，不沿用前年度完成成果抵免。
- 歷年完成日期、時數、歷次成績及逾期狀況分開保留。
- 固定年度截止日與每年必修是不同設定，不能因設定固定日期就自動視為每年重訓。
- 年度截止日之後才到職或接任的人，可依課程設定「指派後指定天數內補訓」或「當年度免修、次年度開始」。

### 8.4 調職與兼任

- 調職或新增兼任職務，以該職務接任日計算新訓練期限。
- 原職務未完成的課程，在該職務不再適用後取消必修要求，保留紀錄。
- 若新職務仍要求同一門課，繼續保留要求。
- 同課程、同年度、同版本合併一次受訓，採較早期限並保留全部來源，細節見第 16 節。
- 取消列管不可顯示為已完成或測驗及格。

## 9. 課程與教材

- 教材支援 PDF、平台內網頁文字及 YouTube 影片。
- 一門課可包含多份與多種教材。
- YouTube 以連結設定，在平台內嵌播放。
- 可設定課程最低總學習時數與及格分數。
- 可分次累計同一課程學習時間。
- 以同一課程內所有教材的有效學習時間合計判定時數。
- 不要求每份教材分別達標。這是使用者修正後的最終規則，取代早先逐份達標的討論。
- 同一課程時數不可直接抵用其他課程。

範例：一門課含 PDF、文字與影片，要求 60 分鐘，三者有效時間合計達 60 分鐘即可開放測驗。不可另外強制每份教材讀滿指定時間。

## 10. 有效學習計時

| 情況 | 計時規則 |
| --- | --- |
| 教材在前景 | 符合其他條件時累計。 |
| 切換背景或縮小視窗 | 暫停累計。 |
| PDF 或文字連續 5 分鐘未操作 | 提示是否繼續並暫停，回來後可繼續累計。 |
| YouTube 在前景持續播放 | 持續累計，不因沒有操作而套用文字教材的閒置限制。 |
| 影片暫停或緩衝 | 不計時。 |
| 倍速播放 | 按實際經過時間累計。例如兩倍速看完 20 分鐘內容，累計 10 分鐘。 |
| 同時開多份教材或多個分頁 | 同一帳號最多計入一份時間，不重複加總。 |

必須顯示實際計時狀態，不能顯示正在累計但實際未保存。重複請求、重新整理與斷線後補送不得造成重複累計。時間可信度與保存方式由 Codex 在技術規劃中提出，不預先指定框架。

## 11. 題庫與測驗

### 11.1 開放及完成條件

- 課程總學習時數達標後才能開始測驗。
- 達標後重考不需重新累計已達標時數。
- 可不限次數重考至及格。
- 正常課程需同時時數達標與測驗及格才算完成。
- 完成時間是兩項條件均滿足的時間。
- 完成時間與適用期限比較，判定準時或逾期完成。
- 逾期仍可繼續學習及測驗。
- 教材更新重訓可另外設定是否重考，依第 12 節處理。

### 11.2 題庫與抽題

- 每門課可設定對應題庫、抽題數與及格分數。
- 題型包含單選題、複選題及是非題，全部自動計分。
- 從題庫隨機抽取指定題數，再打亂出題順序。
- 同一次測驗不重複出現同一題。
- 重考重新抽題及排序，允許再次抽到以前考過的題目。
- 題庫可用題數不足，不可啟用測驗。
- 複選題必須全部選對才得分，漏選或錯選不給分。
- 預設各題等分，總分換算 100 分。
- 選項順序隨機、按題型配額或難度配額尚未要求，不當作既定功能。

### 11.3 測驗進行

- 每門課可設定不限時或指定分鐘數。
- 限時到期自動交卷。
- 自動保存作答。
- 中途離開後繼續同一份試卷，不重新抽題。
- 限時測驗離開期間仍持續倒數。
- 交卷未及格後，才可開啟下一次重新抽題的測驗。
- 保留每次試卷題目、題目當時內容、順序、答案、作答、分數與時間，避免日後題庫修改改寫歷史結果。

### 11.4 交卷回饋

| 結果 | 員工可看到的內容 |
| --- | --- |
| 未及格 | 總分、錯題與對應教材段落，不公布正確答案。 |
| 及格 | 完整作答結果、正確答案及解析。 |

答案與解析需受權限控制，不可只在前台隱藏文字。每題需連結至少一份課程教材，可附頁碼、章節或影片秒數，錯題回饋提供可直接開啟的教材入口。

## 12. 教材更新與重新受訓

更新時可選擇兩種模式：

| 模式 | 規則 |
| --- | --- |
| 僅更新內容 | 已完成者維持完成，不要求重讀或重考。 |
| 要求重新受訓 | 保留原完成紀錄，另外設定本次訓練範圍、課程總時數、是否重考與完成期限。 |

重新受訓仍採課程總時數，不改回每份教材分別達標。新舊版本及訓練批次必須能追溯。更新時對進行中的學習與試卷如何處理，見第 16 節。

## 13. 期限調整、停用與紀錄

### 13.1 個別期限調整

- 主管、HR 與管理員在各自權限範圍內可調整個別期限。
- 必填原因。
- 保存原期限、調整前後期限、操作人及操作時間。
- 個別展延不修改課程預設期限，也不影響其他員工。
- 報表同時呈現原期限與調整後期限，保留曾逾期的事實。
- 已完成的訓練紀錄，不因後續展延而改寫。

### 13.2 離職或帳號停用

- 停止登入共用入口與各系統。
- 已登入者也應受到停用限制，不僅阻擋下次登入。
- 停止新訓練指派及提醒通知。
- 未完成要求結束列管，保留停用原因與當時進度。
- 保留已完成、歷次測驗與期限異動紀錄。
- 具查詢權限者仍可查詢歷史資料。
- 不將離職或停用者未完成課程記為及格。

## 14. 前台通知與 Email

| 事件 | 通知對象及內容 |
| --- | --- |
| 新增訓練 | 員工收到課程名稱、期限與課程入口。 |
| 要求重新受訓 | 員工收到本次要求、期限與入口。 |
| 即將到期 | 員工收到剩餘天數、進度與下一步。 |
| 逾期未完成 | 員工收到逾期提醒，所屬部門主管同步收到逾期彙整。 |

已確認預設：

- 到期前 7、3、1 天提醒。
- 逾期後每 7 天提醒一次。
- 後台可調整提醒設定。
- 同一天多門課合併 Email。
- 主管通知列出員工、課程、截止日、逾期天數及目前進度，提供後台入口。
- 多部門主管依部門分組呈現。
- 完成、取消列管或停用後停止對應催辦。
- HR 前台僅顯示個人通知。
- HR 逾期彙整 Email 預設不寄送，管理員可開啟，範圍仍受 HR 授權限制。
- 通知需避免重複寄送，寄送失敗與重新寄送方式由技術規劃提出。

## 15. 匯入、報表與資料責任

### 15.1 Excel 匯入

- 支援批次匯入人員。
- 先預覽檢查結果，再確認匯入。
- 檢查結果須能辨識有問題的資料及原因。
- 不默默覆寫不明確的人員對應。
- 依第 16 節規定提供範本、以 Email 比對、選擇更新欄位、空白不覆寫，全部檢查通過後整批匯入。

### 15.2 Excel 報表

- 支援依部門、人員、職務、課程、年度及完成狀態篩選。
- 匯出範圍遵守主管、HR 與管理員權限。
- 應包含人員、課程、年度或訓練批次、來源職務、要求時數、有效時數、原期限、調整後期限、完成日期、準時或逾期狀態。
- 歷次測驗成績及作答時間需可查詢及匯出。
- 歷史結果不能被題目更新、職務移除或人員停用改寫。

### 15.3 後續設計需要涵蓋的資料概念

這是需求清單，不是已定案的資料表結構：

- 共用帳號、員工、部門、職務與職責。
- 員工任職歷程、到職日、各職務接任日。
- 系統角色、功能權限、部門管理範圍。
- 課程、教材、版本、題庫、題目與教材對照。
- 職務訓練關聯、直接指派、年度或重訓批次。
- 學習活動、有效時間、閱讀位置與播放位置。
- 試卷、抽題快照、作答、成績與及格結果。
- 期限原值、展延歷程、取消列管原因。
- 通知設定、待寄與已寄紀錄、匯入及匯出紀錄。

權限與計時、抽題、交卷、成績計算不得只依賴可被使用者修改的前台狀態。技術方案須說明如何在可信任的執行端落實。

## 16. 補充定案規則

本節納入初版交付後所有已確認決策；與前文重複時，以本節較具體規則為準。

### 16.1 多職務同課程與調職接續

- 同一員工的同課程、同年度、同版本只需完成一次，要求合併顯示，但保留全部職務與指派來源。
- 不同期限採較早者。
- 移除一個職務時，若其他來源仍有效就繼續列管；已形成期限不自動延後。
- 調職後同課程、同年度、同版本，未完成者沿用時數與測驗紀錄，已完成者直接認列。
- 新職務要求不同版本或指定重訓時，建立新的訓練要求。
- 新職務期限較早時採較早者，不因調職自動展延。

### 16.2 教材、題庫與進行中試卷

- 僅更新內容時保留既有時數與進度，不增加原指派時數要求。
- 已開始的測驗固定使用原卷，題庫更新影響下一次新測驗。
- 試卷開始時固定當次題目、配分、及格分數、抽題數及限時設定。
- 要求重訓時另建訓練要求，重新累計指定總時數，依設定決定是否重考；原紀錄保留。

### 16.3 年度、日期與跨年度

- 日期與時間採 Asia/Taipei。
- 截止日以當地翌日 00:00 前為有效範圍，介面呈現當日 23:59:59 截止，避免毫秒比較遺漏。
- 到職或接任當日為第 0 天。7 月 1 日起算 30 天，截止日為 7 月 31 日。
- 每年必修在 1 月 1 日自動產生，年中才符合條件時即時補指派。
- 截止日前加入者維持原年度截止日，可由有權限者調整。
- 截止日後加入者依課程設定補訓或當年度免修。
- 前年度跨年補訓與新年度必修分開完成，不互相抵用。
- 跨年補訓仍標示原義務年度，不以實際完成年份改寫。

### 16.4 成績與測驗操作

- 未及格前，摘要顯示最近一次分數；及格後顯示首次及格分數。
- 所有歷次成績仍可查詢。
- 及格完成後不再開放重考。年度必修及重訓另建立要求。
- 分數顯示到小數點後兩位，及格使用未四捨五入值判斷。
- 等分測驗以正確題數與總題數的精確比例比較及格門檻，避免浮點誤差。
- 交卷前可返回前題、修改答案，也可查看教材；限時持續倒數。
- 同一訓練要求只存在一份進行中的試卷。再次開啟續答原卷。
- 原卷已交卷且未及格後才可重新抽題。
- 正常課程沿用學習時數加測驗及格的完成條件，不新增免測驗正常課程；更新重訓可依已定規則免重考。

### 16.5 重複閱讀與教材異常

- 重讀同教材、重播影片的有效時間繼續累計，仍以課程總時數判定。
- 達標後保留達標資格，不因繼續閱讀取消。
- PDF、文字或影片載入失敗不計時，提示原因並提供重試及回報入口。
- YouTube 禁止內嵌、已刪除或無法播放時，由管理員更換教材。
- 跳到外部 YouTube 網站觀看不認列時數。
- 教材異常不自動判完成。有權限者可修復教材或依原因展延。
- 管理員收到教材問題回報後可在後台查看與標記處理結果。

### 16.6 指派與課程可見範圍

- 管理員設定課程適用全公司或指定部門。
- 主管可從適用所負責部門的已發布課程，挑選職務訓練或加派個別員工並設定期限。
- 員工前台僅顯示自己已指派課程，初期不開放自行選課。
- 課程適用範圍不取代管理權限，不能藉由可用課程取得其他部門人員資料。
- 課程更新與發布仍由管理員負責。

### 16.7 職務說明書直接在系統建立

- 第一版直接在系統建立與編輯職務說明書，不提供 PDF 附件上傳、文件匯入或自動解析。
- 基本欄位為職務名稱、所屬部門、職務目的。
- 工作職責逐項新增、修改、排序及選擇是否連結課程。
- HR 依授權部門維護草稿，後臺管理員發布。
- 保存每次發布的版本、內容、修改人、時間與修改摘要。
- 第一版不做多層簽核。
- 新版發布後才套用訓練變更，草稿修改不影響員工。
- 新增訓練自動指派，移除要求只在全部來源失效時取消列管，不能刪除歷史結果。

### 16.8 開課期間

課程開放期間與個人的完成期限是兩個獨立設定。

| 模式或狀態 | 規則 |
| --- | --- |
| 永久開課 | 不設結束日期，持續開放；可選擇立即或未來起始時間。 |
| 限期開課 | 設定開始與結束日期時間。 |
| 尚未開課 | 已指派員工可看資訊，不能學習計時或開始測驗。 |
| 開課中 | 可學習與測驗，個人期限仍各自計算。 |
| 已結束 | 不刪資料，停止學習計時及開始新測驗。 |

- 已結束但有進行中試卷，可完成原卷，仍受原測驗限時。
- 未完成者標示「課程已結束、未完成」，不能直接當成取消列管。
- 管理員延長開課後，可接續原進度。
- 新指派時課程已結束，或個人期限超過結束日，顯示衝突警示。
- 不自動縮短個人期限，也不自動延長開課。
- 管理員可延長開課、調整指派設定，或填寫原因保留衝突。
- 自動指派即使衝突仍保留要求，列入後台待處理並向員工說明。
- 尚未解決的自動衝突標為待處理，不假造管理員已填原因。
- 因課程關閉無法學習時暫停催辦，恢復開課後依目前狀態恢復提醒。
- 通知暫停不會抹除已逾期或造成逾期的歷史。

### 16.9 人員與課程生命週期

- 員工復職或重新啟用沿用原身分及紀錄，依目前職務判斷應修課程。
- 已取消列管的舊要求不自動恢復；仍應修時建立新要求並保留歷史關聯。
- Email 由管理員更新登入對應，保留員工身分及全部紀錄，不另建員工。
- 重複人員不自動合併，第一版由管理員停用與修正，不提供自動帳號合併。
- 課程停用停止新指派，既有未完成要求取消列管、保存原因並停止催辦。
- 課程停用與開課結束分開。開課結束可接續原要求，停用則結束列管。
- 已有指派或學習紀錄的課程不得硬刪，只能停用。
- 僅未曾使用且無紀錄的草稿可刪除。

### 16.10 名冊、系統資格與匯入

- 共用名冊維護姓名、Email、到職日、部門、職務及啟用狀態。
- 教育訓練與零食投票使用資格分開，新增員工不自動取得所有系統資格。
- 既有零食資格與紀錄全部保留，教育訓練資格另行批次設定。
- Excel 提供範本，以 Email 比對既有人員，預覽新增、更新及錯誤。
- 明確選擇更新欄位，空白預設不覆寫。
- 有錯誤先修正，全部通過後整批匯入，不能只完成部分人員。
- 保存匯入操作紀錄與執行結果。
- 缺少到職日等必要資料時明確標示，禁止捏造日期自動計算期限。

### 16.11 通知與共用登入

- HR 彙整 Email 預設關閉，管理員可開啟；內容依 HR 授權範圍。
- 逾期通知所有被設定為該部門訓練管理者的主管，不依職稱猜測收件人。
- 同一收件人同一天合併一封，兼任主管按部門分組。
- 預設每天臺灣時間 09:00 彙整寄送，管理員可調整時間。
- 登出任一系統，同瀏覽器中的入口及其他系統同步登出。
- 共用電腦模式一致套用，閒置 30 分鐘登出。
- 切換系統本身不能重置閒置時間或要求重新登入；後續有效操作仍可更新最後活動時間。
- 同一瀏覽器多分頁共用狀態，登入失效、員工停用與登出必須同步。
- 有效學習期間如何與閒置登出協調，依第 19 節工程預設處理。

### 16.12 客服系統後續擴充

這是已確認的未來擴充需求，第一版不實作客服業務或呼叫未知的客服 API。

- 系統目錄採可擴充設計，第一版包含教育訓練與零食投票，預留 customer-service 系統代碼。
- 各系統可設定名稱、入口、啟用狀態、排序、使用資格及管理入口。
- 客服未接入前預設停用，不顯示可點入的空入口，也不對外宣稱已串接。
- 未來客服使用相同共用員工身分及登入入口，不另外建立一套員工帳號。
- 客服使用資格、功能權限及管理範圍獨立設定，不沿用訓練或零食管理員權限。
- 身分對應採穩定員工識別碼，Email 只是可變更的登入與聯絡資料。
- 登入、停用、登出、系統入口與存取檢查保留共用介面，後續可以接入客服。
- 第一版不將客服案件、客戶個資、客服角色、對話或內容同步到其他模組。
- 客服實際儲存庫、現有身分對應及介接方式，於該階段讀取實際系統後決定，不自行推測。
- 預留跨系統連結與事件的擴充位置，不為此提前建造通用整合平台。

## 19. 可直接採用的工程預設

本節是本次規格整理補充的工程決策，目的是讓 Codex 可以實作，不是聲稱使用者逐項指定了資料表或框架。

### 19.1 整合邊界與路由

- 優先延伸現有 snack-vote 專案，在同一來源網域整合入口與模組，避免先建兩套登入交換系統。
- 保留現有技術棧與 Supabase 身分服務，先核對實際使用入口與版本再改。
- 共用同一 Supabase Auth client 及工作階段，不在切換模組時再次登入或執行撤銷其他工作階段。
- 零食既有連結保持可用，新增入口可採 /portal、/training 與 /training/admin；若專案實際採 hash 路由，使用對應 hash 路徑並處理舊連結。
- 客服接入點為系統註冊設定與共用驗證介面，第一版只保留停用項目，不實作客服業務。
- 原工作地點不得直接視為部門，兩者分開對應。
- 現有零食 admin 不自動取得訓練管理員；用一次性、明確的管理員初始化方式設定，不能對全體自動授權。

### 19.2 後端責任與資料約束

- 學習有效時間、及格判斷、抽題、期限、角色與範圍均以可信任後端為準。
- 純靜態前台不保存服務管理金鑰。需要排程與管理操作時使用專案適合的後端函式或工作程序。
- 所有資料讀取、修改及匯出均檢查使用資格、角色及部門範圍。Supabase 資料直讀路徑須有對應存取政策。
- 以穩定員工 id 連結紀錄，Email 改變不改外鍵。
- 課程版本及已指派要求保留規則快照，試卷保留題目與計分快照。
- 年度、課程版本、員工與批次具唯一約束。取消列管後重新指派使用新批次，避免復職被舊唯一鍵阻擋。
- 每個要求只允許一份進行中試卷。交卷、抽題、合併來源、年度生成與通知均可安全重試。
- 草稿與正式發布版本分開，更新歷史採新增不可覆寫紀錄。
- 分數計算保存正確題數與總題數；分數摘要顯示與及格判斷分離。
- 第 13 節的已完成紀錄不因後續展延改寫，調整操作與歷史準時判定分開保存。

### 19.3 狀態與完成判定

分開保存要求生命週期、完成結果、開課狀態及逾期狀態，不把它們塞成互相覆蓋的單一狀態。

- 要求生命週期為有效、已取消列管或年度免修。
- 學習階段為未開始、學習中、可測驗、測驗中、未及格或已完成。
- 課程另有未開課、開課中、已結束與已停用。
- 逾期以適用期限、完成時間及目前時間計算，同時保留原期限歷史。
- 每個前台畫面由以上狀態決定可用按鈕。未完成但已結束需顯示原因，不誤導員工尋找無法使用的測驗。
- 正常完成需學習秒數達門檻且試卷及格。免重考重訓僅需本次時數達標。
- 一次性課程以一次性週期識別，年度課程以義務年度識別，重訓另有批次識別。
- 同課程不同訓練批次不得因版本碰巧相同就互相抵用。
- 移除來源後只有全部有效來源消失才取消列管。移除來源本身不放寬已保存的截止日。

### 19.4 計時與工作階段

- 前台只發送活動與播放器狀態，不能自行提交任意累計秒數。
- 使用後端授予的單一計時租約及遞增序號，每 15 秒保存心跳。新分頁取得租約後舊分頁暫停。
- 有效累計不超過後端實際經過時間與已確認心跳區間。重送相同序號不重複計入。
- 中斷後不信任前端聲稱的離線時數，顯示最後已保存時間。
- 文字教材有效活動以操作及可見性判斷，五分鐘未操作暫停。
- 影片只在前景且播放器處於播放狀態時累計，跳轉影片位置不產生時間。
- 有效前景閱讀或播放屬共用電腦有效活動；背景、暫停及已因閒置暫停不延長登入。防止已允許的長影片正常觀看被 30 分鐘閒置登出打斷。
- 跨模組共用最後有效活動時間，切換頁面本身不重新開始 30 分鐘計時。
- 舊裝置撤銷與多人分頁租約分開處理，不將同瀏覽器切換模組誤判新裝置登入。
- 瀏覽器狀態無法保證使用者真的在閱讀，交付說明需如實描述「有效前景時間」，不可宣稱可完全防掛網。

### 19.5 測驗與教材快照

- 開始測驗後端先驗證員工、要求、開課、計時門檻及現存試卷。
- 抽題與隨機排序在後端建立固定試卷，不重新整理就換題。
- 作答請求只保存該員工的答案；正確答案在允許回饋前不下發。
- 交卷在同一交易完成狀態鎖定、評分、及格及完成時間紀錄。
- 到期以後端時間為準，背景排程或下一次存取都必須完成超時交卷，使用截止前已接受的作答。
- 符合期限的交卷以伺服器接受時間判定。自動交卷以測驗到期時間及已保存作答判定。
- 課程結束後已開試卷仍可交卷，但不能無限重開或重新抽題。
- 未及格時只回傳已允許的錯題與教材資訊，及格才提供答案解析。

### 19.6 通知、匯入與環境

- 通知以收件人、臺灣日期、通知類型及訓練要求去重，寄送前重新檢查是否仍需提醒。
- 系統內通知事件可即時建立，Email 按每日設定時間彙整。
- 共用入口登出不等於結束學習或取消受訓要求。
- Excel 範本提供姓名、Email、到職日、部門、職務、接任日、啟用狀態、系統資格及範例列。
- 匯入到預覽用暫存，確認時重新驗證權限與資料版本，於交易中整批提交。
- 匯出至少有訓練總表、測驗歷次成績及期限異動表，使用相同查詢權限。
- 本機及測試使用假員工及郵件攔截，正式 SMTP、服務金鑰及實際收件者不可進入測試設定。
- 資料庫遷移不得覆寫既有零食活動、員工或採購資料。
- 欠缺憑證時完整列出變數名稱與設定位置，不猜金鑰、不把缺權限視為產品規則未決。
